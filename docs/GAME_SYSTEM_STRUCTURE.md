# 스마트폰 AR 게임 및 센서 처리 시스템 구조

## 1. 개발 환경 및 AR 구성

- **Unity 6** 기반 Android 앱으로 개발하고, **AR Foundation 6.6 + Google ARCore**로 카메라 화면 위에 몬스터를 배치
- 스마트폰을 활에 가로(Landscape)로 거치하여, AR 카메라가 바라보는 방향을 그대로 **활의 조준 방향**으로 사용 (화면 중앙 조준점)
- 게임 진행 관리 모듈을 중심으로 조준·발사 감지·판정·몬스터·화면·통신 모듈을 **이벤트 기반**으로 분리하여 연결
- 범위 크기, 화살 수, 제한 시간, 발사 기준값, 몬스터별 애니메이션·체력 등을 **ScriptableObject 설정 파일**로 분리하여 코드 수정 없이 조정 가능하도록 구성

## 2. 조준 기준점 설정 및 몬스터 활동 범위

- 게임 시작 후 사용자가 쏠 방향을 겨누고 **"방향 정하기" 버튼을 누르거나 실제로 활을 쏘면** 그 방향을 정면 기준점(중앙점)으로 설정
- 버튼을 누르는 손에 폰이 흔들리는 것을 피하기 위해 **0.3초 전 조준 방향**을 사용하고, 활을 쏴서 정할 때는 충격 직전 방향을 사용
- 활이 옆으로 기운 정도(롤)는 조준점을 움직이지 않으므로 기준점에서 제외
- 기준점 앞 **좌우 ±26°, 상하 ±13°, 거리 3.5m** 범위를 AR 사각형 테두리로 표시하고, 몬스터는 이 범위 안에서만 이동
- 범위를 미터가 아닌 **각도 단위**로 정해 방 크기와 관계없이 같은 난이도 유지
- 중앙점은 튜토리얼에서만 설정할 수 있으며, 설정 후 4초 동안 범위를 확인하고 다시 정할 수 있음

## 3. 발사 감지 및 명중 판정

- **Input System 가속도 센서**를 200Hz로 요청하고, 화면 갱신(초당 30회)과 별도로 **들어오는 센서 값을 모두 수신**하여 시위를 놓는 짧은 충격도 놓치지 않도록 처리
- 현재 가속도와 천천히 따라가는 평균값(중력 + 손의 느린 움직임)의 차이를 충격으로 계산하여 **2g 이상이면 발사**로 판정
- 한 번 발사로 판정한 뒤 1초 동안은 다시 판정하지 않아 진동으로 인한 중복 발사 방지
- 발사 충격으로 화면이 흔들리기 전인 **충격 0.05초 전의 조준 방향**으로 명중을 판정 (최근 조준 방향을 계속 기록해 두고 조회)
- 조준선이 몬스터 이미지 영역을 지나면 명중으로 처리하고, 화살이 닿은 자리에 명중(별빛)·빗나감(충격) 이펙트를 AR 공간에 표시
- **정확도**: 조준점과 몬스터 중심 사이 각도로 계산 (정중앙 100%, 10° 이상 벗어나면 0%)
- **조준 안정도**: 발사 직전 1초 동안 조준 방향의 평균 흔들림으로 계산 (0.5° 이하 100%, 5° 이상 0%)
- 점수는 명중 1발당 1점, 명중률·정확도·조준 안정도는 게임 시작부터 누적하여 계산

## 4. 도끼 튜토리얼 (개발 중)

- 오디세우스의 **도끼 시험**을 모티브로, 중앙점 설정 후 1스테이지 전에 진행하는 사격 연습 단계
- 정한 방향으로 **도끼 6자루를 2m 앞부터 0.25m 간격으로 한 줄로 배치**하고, 도끼를 좌우로 엇갈리게 세워 **날 구멍만 일직선**이 되도록 구성
- 가까운 도끼부터 조준선이 구멍 안을 지나는지 검사하여 **모든 구멍을 통과해야 성공**, 막히면 그 도끼 위치에 빗나감 이펙트 표시
- 중앙점을 정한 자리에서 벗어나면 구멍이 어긋나 보여, 실제로 줄을 맞춰 서서 쏘도록 유도
- 화살 3발을 제공하고, 통과하거나 화살을 다 쓰면 2초 뒤 1스테이지 시작 ("건너뛰기" 버튼 제공)
- 연습 단계이므로 **점수와 태블릿 전송 기록에서 제외**하고, 설정에서 끌 수 있음
- 몬스터와 도끼가 **같은 판정 방식(공통 인터페이스)**을 사용하여 하나의 판정 로직으로 처리

## 5. 스테이지 및 몬스터

- **스테이지 3개**: 1스테이지 폴리페모스 → 2스테이지 망량 → 3스테이지 세이렌
- 스테이지마다 **화살 3발, 제한 시간 60초**, 몬스터 **체력 2** (두 번 명중시키면 처치 → 스테이지 클리어)
- 화살이나 시간을 모두 쓰면 실패로 처리하되, 결과 화면을 보여 준 뒤 다음 스테이지로 진행
- 몬스터는 항상 사용자를 바라보는 **2D 빌보드 이미지**로, 대기·이동·피격·쓰러짐 **프레임 애니메이션** 적용
- 몬스터별 이동 방식
  - **폴리페모스(걷기)**: 좌우로 걷다가 무작위 위치에서 1.5초 멈춰 대기 동작, 멈춘 뒤 최소 3초는 계속 이동
  - **망량(떠다니기)**: 좌우로 천천히 떠다니며 6초 주기로 위아래 오르내림
  - **세이렌(날기)**: 1~1.5초 제자리 비행 후 범위 안 다른 위치로 1초 만에 날아가며, 비행 중 기울어지고 깃털을 떨어뜨림
- 명중 시 붉게 번쩍이며 **피격 애니메이션**, 처치 시 **쓰러짐 애니메이션** 후 서서히 사라짐 (세이렌은 바닥으로 떨어지며 쓰러짐)

## 6. 게임 진행 및 화면 구성

- 진행 순서: **메인 화면 → 중앙점 설정 → 도끼 튜토리얼 → 스테이지 1~3 (스테이지마다 결과 화면) → 메인 화면**
- 메인 화면: 게임 시작, 태블릿 연결 버튼 제공
- 게임 화면: 화면 중앙 조준점, 상단에 스테이지 번호·남은 화살(금색/회색 아이콘)·남은 시간 표시
- **일시정지**: 게임 시간과 몬스터를 멈추고 정지 중 발사는 무시, "계속하기" / "메인 화면으로" 선택
- **결과 화면**: "n STAGE CLEAR! / FAILED", 최종 점수·명중률·조준 안정도 표시, 고해상도 몬스터 이미지에 대기 동작 적용
- 결과 화면에서 **5초 카운트다운** 후 다음 스테이지로 자동 진행 (마지막 스테이지 후 메인 화면)
- Android 뒤로 가기 버튼으로 언제든 메인 화면 복귀

## 7. 태블릿 연동 및 게임 데이터 전송

- 같은 Wi-Fi에서 **UDP Socket + JSON** 형식으로 통신 (폰 수신 포트 47800, 태블릿 포트 47801)
- "태블릿 연결" 버튼을 누르면 **4자리 연결 코드와 8자리 session**을 만들고 pair_offer를 0.5초마다 브로드캐스트
- 태블릿이 코드를 입력해 보낸 pair_request의 **코드·session이 일치하면 pair_confirm**으로 연결 수락
- 연결 후 1초마다 ping으로 상태를 유지하고, 끊기면 기기에 저장한 연결 정보로 hello를 보내 **코드 재입력 없이 재연결**
- 게임 진행 이벤트 전송
  - **game_start**: 게임 시작 (게임 구분용 gameId)
  - **stage_start**: 스테이지 번호와 몬스터 종류
  - **shot**: 발사마다 명중·처치 여부, 정확도, 조준 안정도
  - **stage_end / game_end**: 클리어 여부, 누적 점수·명중률·평균 정확도·평균 조준 안정도
- 게임 기록은 빠지지 않도록 태블릿의 **ACK 응답이 올 때까지 0.25초마다 최대 8번 재전송**하고, seq 번호로 중복을 구분할 수 있게 전송
- 연결이 잠시 끊긴 동안의 기록은 보관했다가 재연결되면 이어서 전송
- 수신은 별도 스레드에서 처리하고 게임 반영은 메인 스레드에서 처리하여 게임 진행이 멈추지 않도록 구성

# Be ODYSSEUS 핵심 기술

휴대폰을 활에 장착해 AR로 조준하고, 시위를 놓는 순간의 충격을 센서로 감지해 공간 속 몬스터를 맞히는 양궁 게임입니다.
게임 기록은 서버 없이 같은 와이파이의 태블릿으로 실시간 전송합니다.

- 개발 환경: Unity 6, AR Foundation / ARCore 6.6, Input System, Android(IL2CPP, ARM64)
- 시험 기기: 갤럭시 S23 Ultra

---

## 1. AR 조준

- 휴대폰을 활에 가로로 장착하고, ARCore가 추적하는 카메라의 위치와 방향(6자유도)을 그대로 조준 방향으로 사용합니다.
- 화면 중앙의 조준점이 화살이 날아갈 방향입니다.
- 매 프레임 카메라 갱신이 끝난 뒤 조준 방향을 시각과 함께 기록하고, 최근 3초 분량을 보관합니다.
- 기록 시각은 센서 입력과 같은 시간축을 사용하므로, "충격이 온 순간 직전의 조준 방향"을 정확히 찾을 수 있습니다.
- AR 추적이 안정된 상태일 때만 조준을 신뢰하고, 그 전에는 "AR 준비 중" 안내를 표시합니다.

## 2. 가속도 센서 기반 발사 감지

- 가속도 센서를 200Hz로 요청합니다.
- 화면은 초당 30회 갱신되지만, 센서 값은 입력 이벤트 단위로 받아 프레임 사이에 들어온 값까지 하나도 빠짐없이 처리합니다. 그래서 수 밀리초짜리 짧은 충격도 놓치지 않습니다.
- 느리게 따라가는 기준값(시간 상수 0.3초)을 두고, 현재 가속도와 기준값의 차이를 충격으로 계산합니다(고역 통과 방식).
  - 중력과 손의 느린 움직임은 기준값에 흡수되어 제거되고, 시위를 놓는 순간의 급격한 변화만 남습니다.
- 충격이 2g 이상으로 올라가는 순간(상승 구간)을 발사로 판단합니다.
- 한 번 발사로 판단한 뒤 1초 동안은 다시 발사로 보지 않아, 한 번 쏠 때 충격이 여러 번 튀는 것을 막습니다.
- 센서 콜백 안에서 게임 상태를 바꾸지 않고, 발사 신호를 큐에 넣었다가 다음 프레임에 처리해 안정성을 확보합니다.
- 기기마다 센서 시각이 입력 시각과 1초 이상 어긋나면 입력 시각으로 대신해 판정이 틀어지지 않게 합니다.

## 3. 반동 보정 명중 판정

- 명중 판정은 충격이 온 시각보다 0.05초 앞선 조준 방향으로 합니다. 시위를 놓는 충격으로 화면이 흔들린 방향은 판정에 쓰지 않습니다.
- 조준선(카메라 위치, 조준 방향)과 몬스터 이미지 평면의 교차점을 구합니다. 교차점이 몬스터 이미지 영역 안이면 명중입니다.
- 교차점이 지나치게 멀리 생기는 경우(크게 빗나간 사선)는 기준 거리의 지점을 화살이 닿은 자리로 사용합니다.

## 4. 조준 안정도와 정확도 측정

- **조준 안정도**
  - 발사 직전 1초 동안의 조준 방향 기록으로 평균 방향을 구합니다.
  - 각 순간의 방향이 평균 방향에서 벗어난 각도의 평균을 흔들림으로 봅니다.
  - 흔들림이 0.5° 이하면 100%, 5° 이상이면 0%이며, 그 사이는 비례해 계산합니다.
  - 활의 좌우 기울기(롤)는 조준점을 움직이지 않으므로 제외하고 방향만 봅니다.
- **정확도**
  - 조준 방향과 몬스터 중심을 잇는 방향 사이의 각도로 계산합니다.
  - 정중앙이면 100%, 10° 이상 벗어나면 0%입니다.
- 발사 한 발마다 명중 여부, 정확도, 조준 안정도, 흔들림 각도, 충격 세기를 함께 기록해 "왜 맞았는지/빗나갔는지"를 추적할 수 있습니다.

## 5. 정면 기준 설정 (캘리브레이션)

- 게임 시작 시 사용자가 쏠 방향을 겨누고 버튼을 누르거나 활을 한 번 쏘면, 그 방향을 정면 기준으로 정합니다.
  - 버튼은 누르기 0.3초 전의 조준 방향을 사용해 화면을 누르는 손떨림을 피합니다.
  - 활을 쏘면 발사 판정과 같은 방식(충격 0.05초 전 방향)을 사용합니다.
- 활의 좌우 기울기(롤)는 제외하고 좌우·위아래 방향만 기준으로 저장합니다.
- 기준을 정한 뒤 4초 동안 활동 범위 테두리를 공간에 보여 주고, 그동안 다시 정할 수 있습니다.

## 6. 각도 기반 AR 경기장

- 몬스터의 위치를 미터가 아니라 "정면에서 좌우·위아래로 몇 도"로 다룹니다.
- 정면 기준 좌우 ±26°, 위아래 ±13° 범위에 몬스터가 공간에 고정되어 움직입니다.
- 범위를 각도로 정의해 방의 크기나 벽까지의 거리와 상관없이 같은 난이도를 유지합니다.
- 몬스터 크기만큼 범위 안쪽으로 이동 한계를 줄여, 몬스터가 범위 밖으로 삐져나가지 않습니다.
- 스테이지마다 몬스터 거리를 2.8m → 3.15m → 3.5m로 늘려, 각도 범위는 같게 두고 몬스터만 점점 작게 보이도록 난이도를 높입니다.

## 7. AR 공간 몬스터

- 2D 픽셀아트 이미지를 공간에 띄우고, 위아래는 세운 채 좌우로만 회전해 항상 플레이어를 바라보게 합니다(빌보드).
- 스프라이트 시트의 대기·이동·피격·쓰러짐 프레임을 재생하는 애니메이션 시스템입니다. 몬스터별 설정은 데이터 파일로 분리되어 있어 코드 수정 없이 조절합니다.
- 스테이지별 이동 패턴이 다릅니다.

| 스테이지 | 몬스터 | 이동 패턴 |
|---|---|---|
| 1 | 폴리페모스 | 좌우로 걷다가 3~6초마다 멈춰 쉼, 범위 끝에서 방향 전환 |
| 2 | 망령 | 좌우로 이동하며 위아래로 둥실 떠다님 |
| 3 | 세이렌 | 0.5~0.8초 머물다가 범위 안 다른 위치로 1초 만에 비행. 가속·감속 곡선, 진행 방향으로 몸을 기울임, 깃털 파티클 |

- 체력은 2이며, 맞으면 붉게 번쩍이며 흔들리는 피격 동작을 합니다. 체력이 다하면 쓰러지는 동작 후 사라지고, 세이렌은 날던 자리에서 바닥으로 떨어집니다.
- 세이렌은 대기 중에 맞으면 피격 동작이 끝나자마자 다른 위치로 날아갑니다.

## 8. 화살 비행 연출과 도달 시점 처리

- 명중 여부는 발사 순간의 조준으로 확정하고, 화면에는 화살이 활 쪽(화면 아래)에서 출발해 날아가는 과정을 보여 줍니다.
- 화살이 실제로 도달하는 순간 몬스터 피격 반응, 점수, 남은 화살 수, 명중 효과가 처리됩니다.
- 비행 중 몬스터가 움직이면 화살이 몬스터를 따라가 정확한 자리에 꽂히고, 꽂힌 뒤에도 몬스터와 함께 움직입니다.
- 명중하면 꽂혀서 감쇠 진동으로 떨린 뒤 사라지고, 빗나가면 지나쳐 날아가며 흐려집니다.
- 옆모습 화살 이미지를 카메라를 향하게 두고 화면상 진행 방향으로 회전시켜, 멀어질수록 작아지는 원근감을 냅니다. 금빛 잔상(트레일)으로 비행 경로를 보이게 합니다.

## 9. 픽셀 단위 다중 평면 통과 판정 (튜토리얼)

- 튜토리얼에서는 엇갈린 도끼 6쌍을 조준선을 따라 앞뒤(2m부터 0.25m 간격)로 배치하고, 화살이 모든 도끼 사이 구멍을 통과해야 성공합니다.
- 판정 범위는 도형 근사가 아니라 이미지 픽셀 그대로입니다.
  - 도끼 이미지의 구멍 안 한 점에서 시작해 투명한 픽셀만 따라 채우는 방식(플러드 필)으로 구멍 영역을 실행 중에 추출합니다.
  - 그래서 화면에 보이는 구멍과 판정 범위가 정확히 일치합니다.
- 조준선이 가장 가까운 쌍부터 차례로 각 도끼 평면과 만나는 점이 모두 구멍 안이어야 통과입니다. 막히면 그 도끼에 화살이 꽂힙니다.
- 기준 위치에서 벗어나면 원근 차이로 구멍이 어긋나 보이므로, 실제로 줄을 맞춰 서야 합니다.

## 10. 게임 진행

- 메인 → 정면 기준 설정 → 튜토리얼 → 스테이지 1~3 → 스테이지별 결과 → 최종 결과 순서로 진행합니다.
- 스테이지마다 화살 3발, 제한 시간 30초이며, 몬스터를 쓰러뜨리면 클리어입니다.
- 결과 화면에는 누적 점수, 명중률, 조준 안정도를 보여 주고, 최종 결과 화면에는 스테이지별 클리어 여부와 명중 수를 함께 보여 줍니다.
- 일시정지하면 남은 시간, 몬스터, 효과가 모두 멈추고, 정지 중의 발사는 무시합니다.

## 11. 휴대폰 → 태블릿 통신

### 11-1. 서버 없는 기기 간 직접 통신
- 같은 와이파이 안에서 UDP로 직접 주고받으며, 메시지 하나가 UDP 패킷 하나(UTF-8 JSON)입니다.
- 포트: 휴대폰 47800(수신), 태블릿 47801(수신)
- 모든 메시지에 공통으로 버전, 송신 기기(phone/tablet), 순번(seq), 세션(8자리)이 들어갑니다.
- 수신은 별도 스레드에서 하고, 처리는 게임 메인 스레드에서 하여 게임 진행을 막지 않습니다.

### 11-2. 4자리 코드 연결
1. 휴대폰이 무작위 4자리 코드와 8자리 세션을 생성합니다.
2. 연결 창이 열려 있는 동안 0.5초마다 코드와 세션, 수신 포트를 와이파이 전체에 브로드캐스트합니다(255.255.255.255와 현재 네트워크의 브로드캐스트 주소).
3. 태블릿에서 화면의 코드를 입력하면 태블릿이 연결 요청을 보냅니다.
4. 휴대폰이 코드와 세션을 확인하고 연결 수락을 보냅니다. 요청이 다시 오면 수락을 다시 보내 수락 메시지 유실에 대비합니다.
- 연결한 태블릿(세션, 주소, 포트)을 저장해 두고, 앱을 다시 실행하면 1초마다 재연결 신호를 보내 자동으로 다시 연결합니다.

### 11-3. 게임 기록 실시간 전송

| 메시지 | 보내는 시점 | 내용 |
|---|---|---|
| 게임 시작 | 게임 시작 버튼 | 게임 ID |
| 스테이지 시작 | 스테이지 시작 | 스테이지 번호, 몬스터 이름 |
| 발사 | 화살이 닿을 때마다 | 스테이지, 발사 번호, 명중, 처치, 정확도, 조준 안정도 |
| 스테이지 종료 | 스테이지 종료 | 클리어 여부, 누적 점수, 명중 수, 발사 수, 명중률, 평균 정확도, 평균 안정도 |
| 게임 종료 | 최종 결과 표시 또는 중간 종료 | 완주 여부, 위와 같은 누적 결과 |

- 정확도, 안정도 같은 0~1 값은 소수 셋째 자리까지 보냅니다.

### 11-4. 신뢰성 있는 전달
- 게임 기록은 태블릿의 수신 확인(ack)을 받을 때까지 0.25초마다 최대 8회 같은 순번으로 재전송합니다.
- 수신 확인에는 받은 메시지의 순번이 들어 있어, 어떤 기록이 도착했는지 정확히 구분합니다.
- 순번을 100개 단위로 미리 저장해, 앱을 다시 실행해도 순번이 이어지고 이전 기록과 섞이지 않습니다.
- 연결이 끊긴 동안 생긴 기록은 대기열(최대 100개)에 보관했다가 재연결되면 전송합니다.

### 11-5. 연결 유지와 자동 복구
- 연결 중에는 1초마다 생존 신호(ping)를 보냅니다.
- 연결이 끊기면 재연결 신호를 브로드캐스트와 마지막 주소로 동시에 보내 다시 찾습니다.
- 연결 해제는 3회 반복 전송해 확실히 전달합니다.
- 수신 포트를 열지 못하면(이전 실행이 포트를 잡고 있는 경우 등) 1초마다 자동으로 다시 엽니다.
- 받은 신호와 송신 실패를 모두 기록하고, 연결 창에 마지막으로 받은 신호와 문제 원인을 바로 표시해 현장에서 연결 문제를 빠르게 진단합니다.
